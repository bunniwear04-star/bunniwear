❓ ที่มาของปัญหา (Problem Statement)

ร้านเสื้อผ้าแฟชั่นสไตล์เกาหลี-มินิมอล bunniwear ต้องการระบบหน้าร้านออนไลน์ที่ช่วยให้ลูกค้าเลือกชมสินค้า เลือกสีและไซส์ คำนวณส่วนลด สรุปยอดสั่งซื้อส่งทาง LINE และสามารถออก ใบเสนอราคา (Quotation) ขนาด A4 เป็นไฟล์ PDF ได้ทันที โดยไม่ต้องพึ่งพาระบบฐานข้อมูลหรือเซิร์ฟเวอร์หลังบ้าน (No Backend) เพื่อประหยัดค่าใช้จ่ายและดูแลรักษาง่าย

🔍 การทบทวนความต้องการ (Review)

  • ทำงานจบในไฟล์ index.html เพียงไฟล์เดียว เปิดใช้งานได้ทันที
  • จดจำรายการสินค้าในตะกร้าได้แม้ปิดหรือรีเฟรชหน้าเว็บด้วย LocalStorage
  • มีระบบช่วยคำนวณไซส์อัตโนมัติ และหน้าต่างดูรายละเอียดสินค้าแบบขยาย (Quick View)
  • รองรับทั้งลูกค้าซื้อปลีก และลูกค้าองค์กรที่ต้องการใบเสนอราคา PDF

ความต้องการของระบบ (FR & NF) และอุปกรณ์ (HW)

3.1 Functional Requirements (FR: ระบบทำอะไรได้บ้าง)

  1. ระบบแคตตาล็อกและค้นหา: กรองสินค้าตาม 5 หมวดหมู่ ค้นหาชื่อสินค้า และเรียงลำดับตามราคา/ความนิยม
  2. ระบบ Quick View: แสดงป๊อปอัปภาพขนาดใหญ่ จุดเด่นเนื้อผ้า เลือกสี ไซส์ และจำนวนชิ้น
  3. ระบบตารางไซส์อัจฉริยะ: รับค่ารอบอกและรอบเอว (นิ้ว) เพื่อประมวลผลแนะนำไซส์ (S, M, L, Free Size)
  4. ระบบตะกร้าและโปรโมชั่น: เพิ่ม/ลดจำนวนสินค้า คำนวณสิทธิ์ส่งฟรีเมื่อครบ ฿990 และลด 10% เมื่อใช้โค้ด BUNNI10
  5. ระบบใบเสนอราคา (Quotation PDF): กรอกชื่อลูกค้า/บริษัท เลขผู้เสียภาษี คำนวณ VAT 7% แปลงยอดเงินเป็นตัวอักษรไทย และพิมพ์/โหลด PDF ขนาด A4
  6. ระบบสรุปออเดอร์และแชท LINE: สร้างใบสรุปคำสั่งซื้อพร้อมปุ่มลอยแชท LINE @bunniwear

3.2 Non-Functional Requirements (NF: คุณภาพของระบบ)

  • Performance: โหลดหน้าเว็บไว คำนวณราคาและสลับหมวดหมู่แบบ Real-time ทันทีโดยไม่รีโหลดหน้า
  • Responsiveness: รองรับการแสดงผลทั้งมือถือ แท็บเล็ต และคอมพิวเตอร์
  • Persistence: บันทึกข้อมูลตะกร้าลงใน LocalStorage ของเบราว์เซอร์อัตโนมัติ
  • Portability: ไม่ต้องใช้เซิร์ฟเวอร์ฐานข้อมูลหลังบ้าน โฮสต์ฟรีบน GitHub Pages ได้ทันที

4. Hardware & Environment (HW: สเปกเครื่องและสภาพแวดล้อม)

  • ฝั่งผู้ใช้งาน (Client): สมาร์ทโฟน (iOS/Android) หรือคอมพิวเตอร์ทั่วไปที่มีเว็บเบราว์เซอร์ (RAM ขั้นต่ำ 2 GB)
  • ฝั่งนักพัฒนา (Dev PC): คอมพิวเตอร์ที่บ้านและที่ทำงาน เชื่อมต่อผ่าน Git และ GitHub Desktop
  • Hosting: GitHub Repository (bunniwear04-star/bunniwear)

📌 คำอธิบายแผนภาพกระแสข้อมูล (DFD) ทั้ง 3 องค์ประกอบ:

  • ผู้เกี่ยวข้องภายนอก (External Entities): มี 2 ฝั่ง คือ 👤 ลูกค้า (Customer) ผู้เลือกซื้อและป้อนข้อมูล กับ 💬 แอดมินร้าน (LINE @bunniwear) ผู้รับใบสรุปคำสั่งซื้อไปจัดส่งสินค้า
  • แหล่งเก็บข้อมูล (Data Stores):
    • • D1: ข้อมูลสินค้า (PRODUCTS) — เก็บข้อมูลเสื้อผ้าทั้ง 8 รุ่นในหน่วยความจำของโปรแกรม
    • • D2: ตะกร้าสินค้า (LocalStorage) — เก็บรายการที่ลูกค้าหยิบใส่ตะกร้าไว้ในเบราว์เซอร์
  • กระบวนการทำงานหลัก (Processes 1.0 - 4.0):
    • • Process 1.0: รับคำค้นหา/หมวดหมู่จากลูกค้า ดึงข้อมูลจาก D1 มาแสดงผลการ์ดสินค้าและหน้าต่าง Quick View
    • • Process 2.0: รับคำสั่งหยิบสินค้าและโค้ดส่วนลด BUNNI10 บันทึกลง D2 และคำนวณยอดรวมพร้อมสิทธิ์ส่งฟรี
    • • Process 3.0: ดึงรายการจาก D2 รวมกับชื่อบริษัท/เลขผู้เสียภาษี/VAT 7% เพื่อสร้างใบเสนอราคา A4 และไฟล์ PDF
    • • Process 4.0: ดึงรายการจาก D2 รวมกับชื่อ-ที่อยู่จัดส่ง เพื่อสร้างใบสรุปคำสั่งซื้อให้ลูกค้าคัดลอกส่งให้แอดมินทาง LINE

5.2 แผนภาพความสัมพันธ์ของข้อมูล (Entity Relationship Diagram: ERD)

erDiagram CATEGORY ||--o{ PRODUCT : "contains" PRODUCT ||--o{ CART_ITEM : "selected_as" CART_ITEM }o--|| QUOTATION_ORDER : "included_in" CATEGORY { string id PK string name } PRODUCT { string id PK string name string category FK number price number originalPrice string_array colors string_array sizes } CART_ITEM { string cartKey PK string id FK string name number price string color string size number qty } QUOTATION_ORDER { string docNo PK string customerName string taxId string phone string address boolean includeVat number grandTotal }

1) ความหมายของคำย่อและชนิดข้อมูลในตาราง (Keys & Data Types)

  • PK (Primary Key - คีย์หลัก): รหัสประจำตัวที่ไม่ซ้ำกันของข้อมูลในตารางนั้น (เปรียบเหมือนเลขบัตรประชาชนของข้อมูล)
  • FK (Foreign Key - คีย์นอก): รหัสที่ใช้เชื่อมโยงอ้างอิงไปยังคีย์หลัก (PK) ของอีกตารางหนึ่ง
  • ชนิดข้อมูล (Data Types): string = ข้อความตัวอักษร, number = ตัวเลขราคาหรือจำนวน, boolean = ค่าความจริง (true/false), string_array = ชุดข้อมูลตัวเลือกหลายค่า เช่น รายการสีและรายการไซส์

2) รายละเอียดของทั้ง 4 ตารางข้อมูล (Entities & Attributes) จากบนลงล่าง

📦 กล่องที่ 1: CATEGORY (หมวดหมู่สินค้า)

ทำหน้าที่เก็บหมวดหมู่เสื้อผ้าทั้งหมดของร้าน

  • id (PK): รหัสหมวดหมู่ เช่น shirts, dresses, pants, outerwear
  • name: ชื่อหมวดหมู่ภาษาไทย เช่น "เสื้อเชิ้ต & เสื้อยืด", "ชุดเดรส & ชุดเซ็ต"

👗 กล่องที่ 2: PRODUCT (ข้อมูลสินค้า)

ทำหน้าที่เก็บรายละเอียดเสื้อผ้าแต่ละรุ่นในแคตตาล็อก

  • id (PK): รหัสสินค้า เช่น bunni-01 ถึง bunni-08
  • name: ชื่อรุ่นสินค้า เช่น "เสื้อเชิ้ตโอเวอร์ไซส์ ผ้าลินินพรีเมียม"
  • category (FK): รหัสหมวดหมู่ที่เชื่อมมาจากตาราง CATEGORY
  • price / originalPrice: ราคาขายจริง และราคาเต็มก่อนลด
  • colors / sizes: รายการสีและไซส์ที่มีให้เลือก

🛒 กล่องที่ 3: CART_ITEM (รายการในตะกร้าสินค้า)

ทำหน้าที่เก็บสินค้าที่ลูกค้ากดเลือกใส่ตะกร้า (บันทึกใน LocalStorage)

  • cartKey (PK): รหัสเฉพาะของรายการในตะกร้า เกิดจาก รหัสสินค้า_สี_ไซส์ (เช่น bunni-01_ขาวครีม_S) เพื่อแยกสีและไซส์ของเสื้อรุ่นเดียวกันได้
  • id (FK): อ้างอิงรหัสสินค้าจากตาราง PRODUCT
  • name / price: ชื่อสินค้าและราคาต่อหน่วย
  • color / size / qty: สีที่เลือก, ไซส์ที่เลือก และจำนวนชิ้น

📄 กล่องที่ 4: QUOTATION_ORDER (ใบเสนอราคา / ใบสั่งซื้อ)

ทำหน้าที่เก็บข้อมูลเอกสารเมื่อลูกค้าออกใบเสนอราคา PDF หรือยืนยันออเดอร์

  • docNo (PK): เลขที่ใบเสนอราคา (QT-2026-XXXX) หรือเลขที่ออเดอร์ (BNW-XXXXXX)
  • customerName / taxId: ชื่อลูกค้าหรือบริษัท และเลขผู้เสียภาษี
  • phone / address: เบอร์โทรศัพท์และที่อยู่จัดส่ง
  • includeVat / grandTotal: สถานะคิด VAT 7% และยอดเงินรวมสุทธิ

3) ความหมายของเส้นเชื่อมความสัมพันธ์ (Crow's Foot Notation)

สัญลักษณ์ ขีดตรง 2 ขีด (||) แทนค่า "หนึ่งเดียว (1)" และสัญลักษณ์ วงกลมกับสามแฉกขากา (o{) แทนค่า "ศูนย์หรือหลายรายการ (0..Many)":

  1. CATEGORY ── contains ──> PRODUCT (1 ต่อ หลายรายการ): หมวดหมู่ 1 หมวดหมู่ สามารถมีสินค้าอยู่ในหมวดนั้นได้หลายชิ้น
  2. PRODUCT ── selected_as ──> CART_ITEM (1 ต่อ หลายรายการ): สินค้า 1 รุ่น สามารถถูกเลือกใส่ตะกร้าได้หลายรายการ (เช่น เลือกเสื้อรุ่นเดียวกันทั้งสีขาวไซส์ S และสีเบจไซส์ M)
  3. CART_ITEM ── included_in ──> QUOTATION_ORDER (หลายรายการ ต่อ 1): สินค้าในตะกร้าหลายรายการ ถูกรวบรวมเข้าไปอยู่ในใบเสนอราคา (หรือใบสั่งซื้อ) 1 ใบ

5.3 การออกแบบ UX/UI

  • Mood & Tone: สไตล์ Seoul Minimal Studio ใช้สีครีมพาสเทล (#fdf8f6) และสีโรสโกลด์-พีช (#da7b5b)
  • Typography: ใช้ฟอนต์ Playfair Display สำหรับโลโก้แบรนด์ และฟอนต์ Prompt สำหรับภาษาไทย
  • Single-Page Experience: เลือกสี/ไซส์บนการ์ดได้ทันที มีแถบแจ้งเตือนยอดส่งฟรีอัตโนมัติในตะกร้า
