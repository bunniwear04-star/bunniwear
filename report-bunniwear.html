2. โจทย์ปัญหาและที่มาของโครงการ (? และ Review)

2.1 ที่มาของปัญหา (Problem Statement): ร้านเสื้อผ้าแฟชั่นสไตล์เกาหลีและมินิมอล bunniwear ต้องการมีเว็บไซต์หน้าร้านออนไลน์ (Landing Page) ที่ช่วยให้ลูกค้าสามารถเลือกชมแคตตาล็อกเสื้อผ้า ดูรายละเอียดเนื้อผ้า เลือกสีและไซส์ คำนวณส่วนลดโปรโมชั่น สรุปยอดคำสั่งซื้อส่งต่อให้แอดมินทาง LINE และสามารถออกเอกสารใบเสนอราคา (Quotation) ขนาดมาตรฐาน A4 เพื่อสั่งพิมพ์หรือบันทึกเป็นไฟล์ PDF ได้ทันที โดยผู้ประกอบการมีข้อจำกัดคือไม่ต้องการเช่าเซิร์ฟเวอร์หรือดูแลระบบฐานข้อมูลหลังบ้าน (No Backend) เพื่อลดต้นทุนและลดความซับซ้อนในการดูแลรักษา

2.2 การทบทวนความต้องการ (Review): จากการทบทวนขอบเขตของระบบร่วมกับผู้ใช้งาน พบว่าระบบต้องทำงานจบภายในไฟล์ HTML มาตรฐานเพียงไฟล์เดียว สามารถจดจำรายการสินค้าในตะกร้าของลูกค้าได้ด้วยหน่วยความจำของเว็บเบราว์เซอร์ (LocalStorage) มีระบบช่วยคำนวณไซส์เสื้อผ้าอัตโนมัติ และรองรับทั้งลูกค้าซื้อปลีกรายบุคคลและลูกค้าองค์กรที่ต้องการใบเสนอราคาเพื่อทำเรื่องเบิกจ่าย

3. กรณีการใช้งานระบบ (Use Case)

ผู้ใช้งานหลักของระบบคือ ลูกค้าผู้เข้าชมเว็บไซต์ (Customer) ซึ่งสามารถโต้ตอบกับระบบหน้าร้าน bunniwear ได้ทั้งหมด 7 กรณีการใช้งานหลัก (Use Cases) ดังนี้

  • UC01 ค้นหาและกรองหมวดหมู่เสื้อผ้า: ลูกค้าเลือกดูสินค้าตามหมวดหมู่ ค้นหาจากชื่อสินค้า และเรียงลำดับตามราคาได้
  • UC02 ดูรายละเอียดสินค้าแบบขยาย (Quick View): ลูกค้าคลิกดูภาพสินค้าขนาดใหญ่ จุดเด่นเนื้อผ้า และสถานะสินค้าพร้อมส่ง
  • UC03 เปิดตารางเทียบไซส์และคำนวณไซส์อัตโนมัติ: ลูกค้ากรอกขนาดรอบอกและรอบเอว (นิ้ว) เพื่อให้ระบบแนะนำไซส์ที่เหมาะสม
  • UC04 เลือกสี ไซส์ และจัดการตะกร้าสินค้า: ลูกค้าเพิ่มสินค้าลงตะกร้า ปรับเพิ่มหรือลดจำนวนชิ้น และลบรายการสินค้า
  • UC05 ใช้โค้ดส่วนลดและคำนวณค่าจัดส่ง: ลูกค้ากรอกโค้ดส่วนลด BUNNI10 เพื่อรับส่วนลด 10% และรับสิทธิ์ส่งฟรีเมื่อครบ 990 บาท
  • UC06 ออกใบเสนอราคา A4 (พิมพ์และบันทึก PDF): ลูกค้ากรอกชื่อบริษัท เลขผู้เสียภาษี เลือกคิด VAT 7% และพิมพ์หรือดาวน์โหลดเป็นไฟล์ PDF
  • UC07 ยืนยันคำสั่งซื้อและส่งแชท LINE: ลูกค้ากรอกชื่อและที่อยู่จัดส่งเพื่อสร้างใบสรุปคำสั่งซื้อ และคัดลอกส่งให้แอดมินทาง LINE @bunniwear
4. ความต้องการของระบบ (FR และ NF) และฮาร์ดแวร์ (HW)

4.1 ความต้องการทางฟังก์ชัน (Functional Requirements: FR)

  1. ระบบสามารถแสดงรายการสินค้าและกรองตามหมวดหมู่ทั้ง 5 หมวดหมู่ ได้แก่ ทั้งหมด, เสื้อเชิ้ตและเสื้อยืด, ชุดเดรสและชุดเซ็ต, กางเกงและกระโปรง, เสื้อคลุมและคาร์ดิแกน
  2. ระบบสามารถแสดงหน้าต่างรายละเอียดสินค้าแบบขยาย (Quick View) พร้อมตัวเลือกสี ไซส์ และจำนวนชิ้น
  3. ระบบสามารถรับค่ารอบอกและรอบเอวเป็นนิ้ว เพื่อคำนวณและแนะนำไซส์มาตรฐาน (S, M, L หรือ Free Size) ให้แก่ลูกค้าอัตโนมัติ
  4. ระบบตะกร้าสินค้าสามารถคำนวณยอดรวม ส่วนลดโปรโมชั่น 10% (โค้ด BUNNI10) และคำนวณค่าจัดส่งด่วน 50 บาท (ส่งฟรีเมื่อยอดสุทธิตั้งแต่ 990 บาทขึ้นไป)
  5. ระบบออกใบเสนอราคาสามารถสร้างเอกสารขนาด A4 คำนวณภาษีมูลค่าเพิ่ม 7% (VAT) แปลงตัวเลขยอดสุทธิเป็นตัวอักษรภาษาไทยอัตโนมัติ และส่งออกเป็นไฟล์ PDF ได้
  6. ระบบสามารถสร้างใบสรุปคำสั่งซื้อพร้อมหมายเลขคำสั่งซื้อ และมีปุ่มลอยสำหรับติดต่อแอดมินผ่าน LINE Official

4.2 ความต้องการที่ไม่ใช่ฟังก์ชัน (Non-Functional Requirements: NF)

  1. ด้านประสิทธิภาพ (Performance): หน้าเว็บสามารถโหลดและประมวลผลการค้นหา กรองหมวดหมู่ และคำนวณราคาได้ทันทีแบบ Real-time โดยไม่ต้องโหลดหน้าเว็บใหม่
  2. ด้านการใช้งาน (Usability & Responsiveness): ส่วนติดต่อผู้ใช้รองรับการแสดงผลทั้งบนหน้าจอสมาร์ทโฟน แท็บเล็ต และคอมพิวเตอร์
  3. ด้านความคงอยู่ของข้อมูล (Persistence): จัดเก็บข้อมูลตะกร้าสินค้าไว้ใน LocalStorage ของเบราว์เซอร์ ทำให้ข้อมูลไม่สูญหายเมื่อรีเฟรชหน้าเว็บ
  4. ด้านความสะดวกในการติดตั้ง (Portability): ทำงานในรูปแบบ Static HTML โดยไม่ต้องใช้เซิร์ฟเวอร์ฐานข้อมูลหลังบ้าน

4.3 ฮาร์ดแวร์และสภาพแวดล้อม (Hardware & Environment: HW)

หมวดหมู่อุปกรณ์ รายละเอียดสเปกขั้นต่ำและสภาพแวดล้อมที่รองรับ
เครื่องผู้ใช้งาน (Client Device) สมาร์ทโฟน (iOS / Android), แท็บเล็ต หรือคอมพิวเตอร์ส่วนบุคคล (RAM ขั้นต่ำ 2 GB)
เว็บเบราว์เซอร์ (Web Browser) Google Chrome, Microsoft Edge, Apple Safari หรือ Mozilla Firefox ที่รองรับ HTML5
เครื่องนักพัฒนา (Developer PC) คอมพิวเตอร์ที่บ้านและที่ทำงาน เชื่อมต่อและซิงค์โค้ดผ่านระบบ Git และ GitHub Desktop
ระบบจัดเก็บและโฮสติ้ง (Hosting) GitHub Repository (bunniwear04-star/bunniwear) และรองรับ GitHub Pages
5. การออกแบบระบบ (DFD, ERD, UX/UI และ Flowchart)

5.1 แผนภาพกระแสข้อมูล (Data Flow Diagram: DFD)

แผนภาพกระแสข้อมูลแสดงทิศทางการรับและส่งข้อมูลระหว่างผู้ใช้งานภายนอก (ลูกค้า และแอดมินร้าน) กระบวนการทำงานหลักทั้ง 4 กระบวนการ (Processes 1.0 ถึง 4.0) และแหล่งเก็บข้อมูล 2 แหล่ง ได้แก่ D1 ข้อมูลสินค้า (PRODUCTS) และ D2 ข้อมูลตะกร้าสินค้า (LocalStorage) ดังนี้

แผนภาพที่ 2 แผนภาพกระแสข้อมูล (Data Flow Diagram) ของระบบร้าน bunniwear
ผู้ส่งข้อมูล / ต้นทาง ข้อมูลที่ส่งเข้า (Input Flow) กระบวนการ (Process) ผลลัพธ์ / ปลายทาง (Output)
ลูกค้า + D1 (ข้อมูลสินค้า) คำค้นหา, หมวดหมู่, ตัวเลือกสีและไซส์ 1.0 ระบบแสดงผลและค้นหาสินค้า แสดงการ์ดสินค้าและหน้าต่าง Quick View แก่ลูกค้า
ลูกค้า คำสั่งหยิบใส่ตะกร้า และโค้ดส่วนลด BUNNI10 2.0 ระบบจัดการตะกร้าและคำนวณราคา บันทึกลง D2 (LocalStorage) และแสดงยอดสุทธิแก่ลูกค้า
ลูกค้า + D2 (ตะกร้าสินค้า) ชื่อบริษัท, เลขผู้เสียภาษี, ที่อยู่, ตัวเลือก VAT 7% 3.0 ระบบออกใบเสนอราคา A4 / PDF เอกสารใบเสนอราคาขนาด A4 และไฟล์ PDF แก่ลูกค้า
ลูกค้า + D2 (ตะกร้าสินค้า) ชื่อผู้รับ, เบอร์โทรศัพท์, ที่อยู่จัดส่ง, วิธีชำระเงิน 4.0 ระบบสรุปคำสั่งซื้อ (Checkout) ใบสรุปคำสั่งซื้อส่งต่อให้แอดมินร้านทาง LINE

5.2 แผนภาพความสัมพันธ์ของข้อมูล (Entity Relationship Diagram: ERD)

แม้ระบบจะทำงานแบบไม่มีฐานข้อมูลหลังบ้าน แต่ภายในโปรแกรมมีการจัดโครงสร้างความสัมพันธ์ของข้อมูลออกเป็น 4 ตารางหลัก (Entities) ที่เชื่อมโยงกันแบบหนึ่งต่อหลายรายการ (One-to-Many) ดังแสดงในแผนภาพที่ 3 และคำอธิบายรายละเอียดทั้ง 3 ส่วนด้านล่าง

แผนภาพที่ 3 แผนภาพความสัมพันธ์ของข้อมูล (Entity Relationship Diagram: ERD)
1. ตาราง CATEGORY (หมวดหมู่สินค้า)
• id (PK : string) — รหัสหมวดหมู่สินค้า   |   • name (string) — ชื่อหมวดหมู่ภาษาไทย
|| ─── contains (1 หมวดหมู่ มีสินค้าได้หลายรายการ : 1 to Many) ─── o{
2. ตาราง PRODUCT (ข้อมูลสินค้า)
• id (PK : string) — รหัสสินค้า   |   • name (string) — ชื่อสินค้า   |   • category (FK : string) — รหัสหมวดหมู่
• price (number) — ราคาขาย   |   • originalPrice (number) — ราคาปกติ   |   • colors / sizes (string_array) — สีและไซส์
|| ─── selected_as (1 สินค้า ถูกเลือกใส่ตะกร้าได้หลายสี/หลายไซส์ : 1 to Many) ─── o{
3. ตาราง CART_ITEM (รายการสินค้าในตะกร้า - เก็บใน LocalStorage)
• cartKey (PK : string) — รหัสเฉพาะในตะกร้า (id_color_size)   |   • id (FK : string) — รหัสสินค้า
• name (string) — ชื่อสินค้า   |   • price (number) — ราคาต่อหน่วย   |   • color / size (string)   |   • qty (number) — จำนวนชิ้น
}o ─── included_in (หลายรายการในตะกร้า ถูกรวมอยู่ในใบเสนอราคา/ใบสั่งซื้อ 1 ใบ : Many to 1) ─── ||
4. ตาราง QUOTATION_ORDER (ใบเสนอราคา / ใบสั่งซื้อ)
• docNo (PK : string) — เลขที่เอกสาร (QT-XXXX / BNW-XXXXXX)   |   • customerName (string) — ชื่อลูกค้า/บริษัท
• taxId (string) — เลขผู้เสียภาษี   |   • phone / address (string)   |   • includeVat (boolean)   |   • grandTotal (number)

คำอธิบายแผนภาพ ERD อย่างละเอียด (แบ่งออกเป็น 3 ส่วน)

ส่วนที่ 1 ความหมายของคำย่อและชนิดข้อมูล: รหัส PK (Primary Key) คือคีย์หลักที่ใช้ระบุความไม่ซ้ำกันของข้อมูลในแต่ละตาราง, รหัส FK (Foreign Key) คือคีย์นอกที่ใช้อ้างอิงความสัมพันธ์ไปยังคีย์หลักของตารางอื่น ส่วนชนิดข้อมูลประกอบด้วย string (ข้อความ), number (ตัวเลขราคาและจำนวน), boolean (ค่าความจริง true/false) และ string_array (ชุดข้อมูลตัวเลือกหลายค่า เช่น รายการสีและไซส์)

ส่วนที่ 2 ความหมายของทั้ง 4 ตารางข้อมูล: (1) ตาราง CATEGORY เก็บรหัสและชื่อหมวดหมู่เสื้อผ้า (2) ตาราง PRODUCT เก็บข้อมูลเสื้อผ้าแต่ละรุ่นโดยอ้างอิงหมวดหมู่ผ่านฟิลด์ category (FK) (3) ตาราง CART_ITEM เก็บรายการสินค้าที่ลูกค้าเลือกใส่ตะกร้าใน LocalStorage โดยใช้ cartKey (เกิดจาก รหัสสินค้า_สี_ไซส์ เช่น bunni-01_ขาวครีม_S) เป็นคีย์หลัก เพื่อให้สามารถแยกบรรทัดรายการกรณีลูกค้าสั่งเสื้อรุ่นเดียวกันแต่คนละสีหรือคนละไซส์ได้ และ (4) ตาราง QUOTATION_ORDER เก็บข้อมูลหัวเอกสารใบเสนอราคาและใบสรุปคำสั่งซื้อ

ส่วนที่ 3 ความหมายของเส้นเชื่อมความสัมพันธ์ (Crow's Foot Notation): สัญลักษณ์ขีดตรงสองขีด (||) แทนค่าหนึ่งเดียว (1) และสัญลักษณ์วงกลมพร้อมสามแฉก (o{) แทนค่าศูนย์หรือหลายรายการ (Many) ได้แก่ (1) หมวดหมู่ 1 หมวดหมู่ มีสินค้าได้หลายชิ้น (2) สินค้า 1 รุ่น ถูกเลือกเป็นรายการในตะกร้าได้หลายสีหรือหลายไซส์ และ (3) รายการในตะกร้าหลายรายการ ถูกรวบรวมอยู่ในใบเสนอราคาหรือใบสั่งซื้อ 1 ใบ

5.3 การออกแบบประสบการณ์และส่วนติดต่อผู้ใช้ (UX/UI Design)

  • แนวคิดการออกแบบ (Mood & Tone): ออกแบบภายใต้แนวคิด Seoul Minimal Studio ใช้โทนสีครีมพาสเทล (#fdf8f6) และสีพีชโรสโกลด์ (#da7b5b) เพื่อให้สอดคล้องกับภาพลักษณ์แบรนด์เสื้อผ้าแฟชั่นสไตล์เกาหลี
  • การออกแบบการใช้งานในหน้าเดียว (Single-Page Experience): ลูกค้าสามารถคลิกเลือกสีและไซส์บนการ์ดสินค้าได้ทันทีโดยไม่ต้องเปลี่ยนหน้า พร้อมแถบคำนวณยอดสั่งซื้อขั้นต่ำเพื่อรับสิทธิ์ส่งฟรีแบบอัตโนมัติ
  • การออกแบบหน้าพิมพ์เอกสาร (Print-Ready Layout): ใช้คำสั่ง CSS @media print ซ่อนแถบเมนูและปุ่มควบคุมทั้งหมดเมื่อสั่งพิมพ์ เหลือเฉพาะหน้ากระดาษใบเสนอราคาขนาด A4 ที่ถูกต้องตามมาตรฐานเอกสารการค้า
