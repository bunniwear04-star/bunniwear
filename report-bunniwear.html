1. ภาพรวมขั้นตอนการวิเคราะห์และออกแบบระบบ

ในการจัดทำโครงงานระบบเว็บไซต์ร้านขายเสื้อผ้าแฟชั่นออนไลน์ bunniwear คณะผู้จัดทำได้วางแผนและดำเนินงานตามขั้นตอนการวิเคราะห์และออกแบบระบบ โดยเริ่มจากการศึกษาสภาพปัญหาของร้านค้าและการทบทวนความต้องการของผู้ใช้งาน (Review) เพื่อนำมากำหนดเป็นกรณีการใช้งานระบบ (Use Case) จากนั้นจึงแยกวิเคราะห์ออกเป็นความต้องการทางฟังก์ชัน (FR) และความต้องการที่ไม่ใช่ฟังก์ชัน (NF) เพื่อใช้กำหนดสเปกอุปกรณ์ฮาร์ดแวร์ (HW) และออกแบบโครงสร้างระบบ ได้แก่ แผนภาพกระแสข้อมูล (DFD), แผนภาพความสัมพันธ์ของข้อมูล (ERD), การออกแบบหน้าจอ (UX/UI) และผังงาน (Flowchart) ก่อนนำไปเขียนโค้ดพัฒนาโปรแกรม (Dev) และทดสอบการทำงานของระบบ (Testing) เทียบกับ Use Case ที่ตั้งไว้ ดังแสดงในแผนภาพที่ 1

4. อุปกรณ์และสภาพแวดล้อม (HW)

จากแผนภาพที่ 1 กระบวนการทำงานมีการตรวจสอบความถูกต้องใน 2 ส่วนหลัก คือ การทบทวนความต้องการของผู้ใช้ก่อนสรุปเป็น Use Case และการนำผลการทดสอบระบบในขั้นตอนสุดท้ายกลับไปเทียบกับ Use Case อีกครั้ง เพื่อให้มั่นใจว่าเว็บไซต์ที่พัฒนาขึ้นสามารถใช้งานได้จริงตามขอบเขตที่กำหนดไว้

2. ที่มาและความสำคัญของโครงงาน

2.1 ที่มาและสภาพปัญหา: ร้านขายเสื้อผ้าแฟชั่นออนไลน์ทั่วไปมักประสบปัญหาเวลาที่ลูกค้าต้องการดูรายละเอียดสินค้าหลายรุ่นพร้อมกัน หรือต้องทักแชทถามราคา ค่าจัดส่ง และไซส์เสื้อผ้าทีละรายการ ทำให้เสียเวลาทั้งฝั่งลูกค้าและแอดมิน นอกจากนี้ ลูกค้าบางกลุ่มที่สั่งซื้อเสื้อผ้าไปใช้ในงานกิจกรรมหรือสั่งซื้อในนามบริษัทมีความจำเป็นต้องใช้เอกสารใบเสนอราคา (Quotation) เพื่อนำไปทำเรื่องเบิกจ่าย ทางผู้จัดทำจึงได้พัฒนาเว็บไซต์ร้าน bunniwear ขึ้นเพื่อให้ลูกค้าสามารถเลือกชมสินค้า คำนวณไซส์ คำนวณส่วนลด และกดพิมพ์หรือดาวน์โหลดใบเสนอราคาเป็นไฟล์ PDF ขนาด A4 ได้ด้วยตนเองผ่านหน้าเว็บไซต์ทันที

2.2 การรวบรวมและทบทวนความต้องการของผู้ใช้: จากการวิเคราะห์ความต้องการของการใช้งานจริง ได้กำหนดให้เว็บไซต์ทำงานแบบหน้าเดียว (Single Page) เพื่อให้เปิดใช้งานได้สะดวกรวดเร็วโดยไม่ต้องติดตั้งระบบฐานข้อมูลหลังบ้าน ใช้ LocalStorage ของเว็บเบราว์เซอร์ในการจดจำรายการสินค้าที่ลูกค้าเลือกไว้ในตะกร้า มีโปรแกรมช่วยเทียบไซส์จากรอบอกและรอบเอว และสามารถสรุปรายการสั่งซื้อเพื่อคัดลอกส่งให้แอดมินทาง LINE ได้ทันที

3. การวิเคราะห์กรณีการใช้งานระบบ (Use Case)

ระบบเว็บไซต์ร้าน bunniwear มีผู้ใช้งานหลักคือ ลูกค้าผู้เข้าชมเว็บไซต์ (Customer) โดยมีกรณีการใช้งานระบบทั้งหมด 7 ส่วน ดังนี้

  • UC01 ค้นหาและเลือกดูหมวดหมู่สินค้า: ลูกค้าสามารถเลือกดูเสื้อผ้าแยกตามหมวดหมู่ พิมพ์ค้นหาชื่อสินค้า และจัดเรียงสินค้าตามราคาได้
  • UC02 ดูรายละเอียดสินค้าเพิ่มเติม (Quick View): ลูกค้าคลิกที่รูปสินค้าเพื่อดูภาพขนาดใหญ่ คำอธิบายเนื้อผ้า และตัวเลือกสีหรือไซส์ที่มีจำหน่าย
  • UC03 เทียบตารางไซส์และคำนวณไซส์เสื้อผ้า: ลูกค้ากรอกขนาดรอบอกและรอบเอว (นิ้ว) เพื่อให้ระบบช่วยแนะนำไซส์ที่เหมาะสม
  • UC04 จัดการรายการสินค้าในตะกร้า: ลูกค้าเลือกสี ไซส์ และจำนวนที่ต้องการเพื่อหยิบใส่ตะกร้า รวมถึงปรับเพิ่มลดจำนวนหรือลบรายการได้
  • UC05 ใช้โค้ดส่วนลดและคำนวณค่าจัดส่ง: ลูกค้ากรอกโค้ด BUNNI10 เพื่อรับส่วนลด 10% และระบบคำนวณสิทธิ์ส่งฟรีอัตโนมัติเมื่อยอดครบ 990 บาท
  • UC06 ออกใบเสนอราคาขนาด A4 (พิมพ์ / PDF): ลูกค้ากรอกข้อมูลชื่อผู้ซื้อหรือบริษัท เลขผู้เสียภาษี เลือกคำนวณ VAT 7% และสั่งพิมพ์หรือบันทึกเป็นไฟล์ PDF
  • UC07 ยืนยันการสั่งซื้อและส่งข้อมูลทาง LINE: ลูกค้ากรอกชื่อ เบอร์โทรศัพท์ และที่อยู่จัดส่งเพื่อสร้างใบสรุปคำสั่งซื้อสำหรับส่งให้แอดมินทาง LINE

4. ความต้องการของระบบและอุปกรณ์ที่ใช้

4.1 ความต้องการทางฟังก์ชัน (Functional Requirements)

  1. แสดงรายการเสื้อผ้าทั้งหมด 16 รายการ แบ่งออกเป็น 4 หมวดหมู่ (หมวดหมู่ละ 4 รายการ) พร้อมระบบค้นหาและเรียงลำดับราคา
  2. เปิดหน้าต่างแสดงรายละเอียดสินค้า (Quick View) เพื่อให้ลูกค้าเลือกสี ไซส์ และระบุจำนวนชิ้นที่ต้องการได้
  3. คำนวณไซส์เสื้อผ้าอัตโนมัติจากค่ารอบอกและรอบเอวที่ลูกค้ากรอก เพื่อแนะนำไซส์ S, M, L หรือ Free Size
  4. คำนวณราคารวมในตะกร้า ส่วนลดโปรโมชั่น 10% (โค้ด BUNNI10) และค่าจัดส่ง 50 บาท (ส่งฟรีเมื่อยอดสุทธิครบ 990 บาทขึ้นไป)
  5. สร้างเอกสารใบเสนอราคาขนาด A4 พร้อมคำนวณภาษีมูลค่าเพิ่ม (VAT 7%) แปลงจำนวนเงินเป็นคำอ่านภาษาไทย และบันทึกเป็นไฟล์ PDF ได้
  6. สร้างข้อความสรุปคำสั่งซื้อพร้อมรหัสออเดอร์ เพื่อให้ลูกค้าคัดลอกส่งให้ร้านค้าผ่านทาง LINE Official (@bunniwear)

4.2 ความต้องการที่ไม่ใช่ฟังก์ชัน (Non-Functional Requirements)

  1. ด้านความเร็วในการทำงาน: กรองหมวดหมู่ ค้นหาสินค้า และคำนวณยอดเงินในตะกร้าได้ทันทีโดยไม่ต้องโหลดหน้าเว็บใหม่
  2. ด้านการรองรับหน้าจออุปกรณ์: จัดวางโครงสร้างหน้าเว็บแบบ Responsive รองรับทั้งโทรศัพท์มือถือ แท็บเล็ต และคอมพิวเตอร์
  3. ด้านการเก็บรักษาข้อมูลตะกร้าสินค้า: ใช้ LocalStorage ของเบราว์เซอร์ช่วยจำรายการในตะกร้า ทำให้ข้อมูลไม่หายเมื่อกดรีเฟรชหน้าเว็บ
  4. ด้านความสะดวกในการนำไปใช้งาน: พัฒนาในรูปแบบเว็บไซต์หน้าเดียว (Static Web) เปิดใช้งานผ่านเว็บเบราว์เซอร์ทั่วไปได้ทันที

4.3 อุปกรณ์ฮาร์ดแวร์และซอฟต์แวร์ที่ใช้ในระบบ

5. การออกแบบระบบ

5.1 แผนภาพกระแสข้อมูล (Data Flow Diagram: DFD)

แผนภาพกระแสข้อมูลของระบบร้าน bunniwear แสดงการส่งต่อข้อมูลระหว่างผู้เกี่ยวข้องภายนอก (ลูกค้า และแอดมินร้าน) กระบวนการทำงานหลักของระบบทั้ง 4 กระบวนการ และแหล่งเก็บข้อมูลในระบบอีก 2 ส่วน ได้แก่ ข้อมูลสินค้า (D1) และข้อมูลตะกร้าสินค้า (D2) ดังแสดงในแผนภาพที่ 2

แผนภาพที่ 2 แผนภาพกระแสข้อมูล (DFD) ของระบบร้าน bunniwear
ต้นทางข้อมูล ข้อมูลที่ส่งเข้า (Input) กระบวนการ (Process) ข้อมูลที่ส่งออก / ปลายทาง
ลูกค้า และ D1 (ข้อมูลสินค้า) คำค้นหา, หมวดหมู่, สีและไซส์ 1.0 ระบบแสดงผลและค้นหาสินค้า แสดงรายการสินค้าและรายละเอียดแก่ลูกค้า
ลูกค้า รายการสินค้าที่เลือก และโค้ดส่วนลด 2.0 ระบบจัดการตะกร้าและคำนวณยอด บันทึกข้อมูลลง D2 และแสดงยอดรวมสุทธิ
ลูกค้า และ D2 (ตะกร้าสินค้า) ชื่อลูกค้า/บริษัท, เลขผู้เสียภาษี, VAT 7% 3.0 ระบบออกใบเสนอราคา A4 / PDF เอกสารใบเสนอราคาขนาด A4 และไฟล์ PDF
ลูกค้า และ D2 (ตะกร้าสินค้า) ชื่อผู้รับ, เบอร์โทร, ที่อยู่, วิธีชำระเงิน 4.0 ระบบสรุปรายการสั่งซื้อ ข้อความสรุปคำสั่งซื้อส่งให้แอดมินทาง LINE

รายละเอียดการทำงานของแผนภาพกระแสข้อมูล (DFD)

  • ผู้เกี่ยวข้องภายนอก (External Entities): มี 2 ส่วน คือ ลูกค้า ซึ่งเป็นผู้เลือกซื้อสินค้าและกรอกข้อมูลการสั่งซื้อ และแอดมินร้านค้า ซึ่งเป็นผู้รับข้อมูลสรุปคำสั่งซื้อจากลูกค้าผ่านทาง LINE เพื่อตรวจสอบและจัดส่งสินค้า
  • แหล่งเก็บข้อมูล (Data Stores): แบ่งเป็น D1 ข้อมูลสินค้า (PRODUCTS) ใช้เก็บข้อมูลเสื้อผ้าทั้ง 16 รายการในตัวแปรของโปรแกรม และ D2 ตะกร้าสินค้า (LocalStorage) ใช้เก็บรายการสินค้าที่ลูกค้ากดเลือกไว้ในเว็บเบราว์เซอร์
  • กระบวนการทำงานหลัก (Processes): ประกอบด้วย กระบวนการที่ 1.0 ค้นหาและแสดงผลสินค้า, กระบวนการที่ 2.0 จัดการตะกร้าและคำนวณราคาสุทธิ, กระบวนการที่ 3.0 สร้างใบเสนอราคาขนาด A4 และไฟล์ PDF และกระบวนการที่ 4.0 สรุปข้อมูลใบสั่งซื้อเพื่อส่งต่อให้ทางร้าน

5.2 แผนภาพความสัมพันธ์ของข้อมูล (Entity Relationship Diagram: ERD)

โครงสร้างข้อมูลภายในระบบแบ่งออกเป็น 4 ตารางหลัก (Entities) ที่มีความสัมพันธ์กันแบบหนึ่งต่อหลายรายการ (One-to-Many) ดังแสดงในแผนภาพที่ 3

แผนภาพที่ 3 โครงสร้างตารางข้อมูลและความสัมพันธ์ (ERD)
ชื่อตาราง (Entity) คีย์หลัก / คีย์นอก แอตทริบิวต์และข้อมูลที่จัดเก็บ (Attributes)
1. CATEGORY (หมวดหมู่) PK: id id (รหัสหมวดหมู่), name (ชื่อหมวดหมู่), desc (คำอธิบายหมวดหมู่)
2. PRODUCT (สินค้า) PK: id, FK: category id (รหัสสินค้า), name (ชื่อสินค้า), category (รหัสหมวดหมู่), price (ราคาขาย), originalPrice (ราคาปกติ), colors (สี), sizes (ไซส์)
3. CART_ITEM (ตะกร้า) PK: cartKey, FK: id cartKey (รหัสรายการในตะกร้า), id (รหัสสินค้า), name (ชื่อสินค้า), price (ราคาต่อชิ้น), color (สีที่เลือก), size (ไซส์ที่เลือก), qty (จำนวนชิ้น)
4. QUOTATION_ORDER PK: docNo docNo (เลขที่เอกสาร), customerName (ชื่อผู้ซื้อ), taxId (เลขผู้เสียภาษี), phone (เบอร์โทร), address (ที่อยู่), includeVat (VAT 7%), grandTotal (ยอดสุทธิ)
สรุปความสัมพันธ์ระหว่างตาราง: CATEGORY (1) ───< (M) PRODUCT (1) ───< (M) CART_ITEM (M) >─── (1) QUOTATION_ORDER

คำอธิบายโครงสร้างตารางและความสัมพันธ์ของข้อมูล

1. คีย์และชนิดข้อมูลที่ใช้: กำหนดให้ PK (Primary Key) เป็นรหัสหลักที่ใช้ระบุข้อมูลแต่ละแถวไม่ให้ซ้ำกัน และ FK (Foreign Key) เป็นรหัสที่ใช้เชื่อมโยงข้อมูลระหว่างตาราง โดยข้อมูลตัวอักษรเก็บในรูปแบบข้อความ (String), ราคาและจำนวนชิ้นเก็บเป็นตัวเลข (Number) และตัวเลือกสีหรือไซส์เก็บเป็นชุดข้อมูลอาเรย์ (Array)

2. หน้าที่ของแต่ละตาราง: ตาราง CATEGORY เก็บข้อมูล 4 หมวดหมู่เสื้อผ้า, ตาราง PRODUCT เก็บรายละเอียดเสื้อผ้าทั้ง 16 รายการโดยเชื่อมกับรหัสหมวดหมู่, ตาราง CART_ITEM เก็บรายการสินค้าที่ลูกค้าเลือกไว้ใน LocalStorage โดยใช้รหัสผสมระหว่างรหัสสินค้า สี และไซส์ (cartKey) เพื่อแยกแต่ละตัวเลือกออกจากกัน และตาราง QUOTATION_ORDER เก็บข้อมูลผู้ซื้อและยอดเงินสุทธิสำหรับสร้างใบเสนอราคาและใบสั่งซื้อ

3. ความสัมพันธ์ระหว่างตาราง: หมวดหมู่สินค้า 1 หมวดหมู่ มีรายการเสื้อผ้าได้หลายรุ่น (1:M), เสื้อผ้า 1 รุ่น สามารถถูกเลือกใส่ตะกร้าได้หลายสีและหลายไซส์ (1:M) และรายการสินค้าในตะกร้าหลายรายการจะถูกรวมเข้าไปอยู่ในใบเสนอราคาหรือใบสั่งซื้อ 1 ใบ (M:1)
